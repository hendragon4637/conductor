## User intent (verbatim)
Given `coverage_gap.py` (currently 40% covered by `test_coverage_gap.py`), raise pytest coverage to ≥80% without changing the production code. Run `coverage run -m pytest && coverage report` to verify.

## Success criteria (deterministic)
- Existing `coverage_gap.py` is NOT modified (production code is frozen)
- Additional tests are added to `test_coverage_gap.py` (or new test files)
- Running `coverage run -m pytest && coverage report` shows ≥80% coverage
- All tests pass (`pytest -q` exit code 0)

## Constraints (clauses)
- k1: must not change the production code file
- k2: must achieve ≥80% line/branch coverage
- k3: must verify coverage via `coverage run -m pytest && coverage report`

## Anti-patterns (what counts as failure)
- modifying production code to improve coverage
- deleting untested code instead of testing it
- achieving coverage with trivial/noop tests
- skipping the receipt marker
