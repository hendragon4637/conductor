# t18 — Circuit breaker

## User intent (verbatim)
Implement a circuit breaker in `circuit_breaker.py` — states CLOSED/OPEN/HALF_OPEN, configurable thresholds. Test state transitions deterministically.

## Domain
backend

## Intent type
implement

## Success criteria (deterministic)
- `circuit_breaker.py` contains a CircuitBreaker class
- Three states: CLOSED (normal), OPEN (failing), HALF_OPEN (probing)
- Configurable: failure_threshold (trips to OPEN), success_threshold (recovers from HALF_OPEN), open_timeout (seconds before going HALF_OPEN)
- When OPEN: calls are rejected immediately (raises CircuitBreakerOpenError or returns a fallback)
- After open_timeout: transitions to HALF_OPEN
- In HALF_OPEN: first call is allowed; if it succeeds, transitions to CLOSED; if it fails, back to OPEN
- Tests use mock time (not real sleep) for deterministic state transitions
- Pytest tests exist; `pytest -q` passes

## Constraints (clauses)
- k1: must implement all 3 states with correct transitions
- k2: must not use time.sleep in tests (use mock/fake clock)
- k3: must support configurable thresholds

## Anti-patterns (what counts as failure)
- missing HALF_OPEN state
- using real time.sleep in tests
- not testing state transitions
- skipping the receipt marker
