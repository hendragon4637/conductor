# t16 — JWT auth on URL shortener

## User intent (verbatim)
Add JWT auth to the URL shortener from M11: `POST /shorten` requires `Authorization: Bearer <jwt>` with valid HS256 signature. Use `python-jose`. Include token-fixture tests for valid/expired/bad-signature cases.

## Domain
backend

## Intent type
implement

## Success criteria (deterministic)
- `POST /shorten` now requires `Authorization: Bearer <jwt>` header
- JWT uses HS256 with a configurable secret
- Valid JWT → endpoint works normally
- Expired JWT → returns 401
- Bad-signature JWT → returns 401
- Uses `python-jose` for JWT operations
- `GET /{code}` does NOT require auth (public redirect)
- Pytest tests exist for all auth cases; `pytest -q` passes

## Constraints (clauses)
- k1: must use python-jose (or python-jose-cryptodome)
- k2: must distinguish expired vs bad-signature
- k3: GET redirect must remain unauthenticated
- k4: must include token fixtures for test

## Anti-patterns (what counts as failure)
- using a different JWT library
- requiring auth on the redirect endpoint
- not testing expired tokens
- skipping the receipt marker
