# t11 — URL shortener

## User intent (verbatim)
Build a URL shortener with FastAPI in `shortener/`. Endpoints: `POST /shorten` returns a 6-char alphanumeric code; `GET /{code}` 302-redirects. Storage: SQLite. Include collision retry. Tests cover happy path, unknown code (404), and idempotency.

## Domain
backend

## Intent type
implement

## Success criteria (deterministic)
- `POST /shorten` accepts `{"url": "..."}` and returns 201 with `{"short_code": "abc123", "original_url": "..."}`
- `GET /{code}` returns 302 redirect to the original URL
- `GET /{code}` returns 404 for unknown code
- SQLite-backed storage
- Collision retry: if generated code already exists, retries at least once
- Validates URL format before shortening
- Pytest tests exist; `pytest -q` passes
- Test uses TestClient (not requests)

## Constraints (clauses)
- k1: must use SQLite for storage
- k2: must include test for 404 on unknown code
- k3: must include test for redirect (302)
- k4: short codes must be exactly 6 alphanumeric characters
- k5: must validate URL format

## Anti-patterns (what counts as failure)
- using in-memory dict instead of SQLite
- missing 404 test
- codes shorter or longer than 6 chars
- using requests instead of httpx TestClient
- skipping the receipt marker
