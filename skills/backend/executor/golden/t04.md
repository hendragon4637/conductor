# t04 — input validation

## User intent (verbatim)
Add POST /signup that accepts {"email": str, "password": str}. Validate email format and that password >= 8 chars using Pydantic. Return 422 on invalid. Include tests for valid and invalid cases.

## Domain
backend

## Intent type
implement

## Success criteria (deterministic)
- POST /signup accepts JSON with email and password
- Valid email format required (must contain @)
- Password must be >= 8 characters
- Returns 201/200 on valid input
- Returns 422 with validation error details on invalid input
- Pydantic model used for request body
- Tests cover valid, invalid email, short password; `pytest -q` passes

## Constraints (clauses)
- k1: must use Pydantic for validation
- k2: must test both valid and invalid cases
- k3: must return proper 422 with error details

## Anti-patterns (what counts as failure)
- manual validation instead of Pydantic
- returning 400 instead of 422
- no test for invalid email format
- no test for short password

trivial
